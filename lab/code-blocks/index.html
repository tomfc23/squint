code blocks

Seven ways for pi's transcript to draw one fenced code block. The same three blocks in every candidate: a ts edit, a diff, and a language-less JSON blob. The comparison is the design and nothing else.

Rendered from pi's live dark theme and hljs. Not screenshots.

  1. Every frame below is drawn by render.mjs: pi's resolved theme colors for chrome, pi's own highlightCode for the code, the glyphs pi and squint already draw. Nothing is a hand-picked hex or a picture of a terminal.
  2. The transcript cannot do per-block affordances: no copy button, no collapse, no hover. Any candidate that needs one is out.
  3. Below about 760px the frames scroll sideways rather than reflow: a real transcript line is 74 columns and a phone is not, so shrinking the type would lie about the fit.
  4. These are the constraints the real renderer has: a block is lines of styled text, drawn at a known width, with highlightCode(code, lang) available and the language optional.

Pick by number: reply 01...06 (or "01 with the heavy bar"). The choice ships as /squint → Code blocks → a style (or /squint card directly). The choice lives in squint, and this page regenerates from the same theme squint reads.

01

Spine

A muted language label, then one left rule per line. No fences; the code carries the block.

borrowed
Claude Code, Cursor CLI, opencode: the left-rule family
best at
long sessions where code should stay quiet
cost
no closing edge; two blocks in a row separate only by the blank line

02

Card

The block is a closed object: rounded corners, label set into the top rail, all four edges ruled.

borrowed
squint's deck direction · Claude Code's box glyph sets
best at
one block you are meant to study, and blocks inside prose
cost
two rail lines per block, and it competes with squint's own tool cards

03

Panel

A full-width ground behind the code and nothing else. The block is a lit surface, not a frame.

borrowed
Warp · ChatGPT and Claude web · pi's own tool panels (toolPendingBg)
best at
the strongest separation with zero glyphs spent on chrome
cost
a panel is heavier than code deserves for one-liners, and it fights the tool panels' meaning

04

Listing

Line numbers in a dim gutter and a stated count. The block reads as a listing you can cite.

borrowed
GitHub and GitLab code view · bat · less -N
best at
quoting back a line ('the guard on line 3'), and diffs
cost
numbering a two-line snippet is ceremony; numbers only ever start at 1

05

Rule

One hairline header with the language in it, then plain indented code. The lightest chrome that still labels.

borrowed
GitHub web's file header · documentation styles
best at
prose-heavy answers where code is a short interruption
cost
no closing edge, and a full-width rule can be mistaken for a markdown hr

06

Chip

The language is a filled badge on the first line, in squint's tool palette. Immediately scannable.

borrowed
squint's badge direction and GitHub's language pill, drawn in pi's blue token
best at
scanning a long answer for 'where is the code'
cost
loud on every block, and it says nothing about where the block ends

What I need from you

One number, plus any dial you want flipped. The winner is a style in squint, picked from its own menu, with off keeping pi's fences. Three worth naming up front, because they change the answer:

  • 01 Spine is the default /squint code spine ships with. It is the quiet default and the one every competitor lands near.
  • 02 Card and 03 Panel spend the most chrome. If code blocks in pi should look like squint's tool cards, 02 is the congruent choice; if they should look like pi's own panels, 03 is.
  • 04 Listing is the only one that changes what you can do with a block afterwards: cite it by line number.
Same content in every frame. Chrome colors resolve from getResolvedThemeColors("dark") in the active pi release; code colors come from pi's highlightCode, so a theme change or a new pi version moves this page with it. Regenerate with node render.mjs; ship a winner with /squint.
